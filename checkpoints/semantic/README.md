# Semantic Checkpoints (versioned)

The anti-amnesia record of the Sovereign Verification Ledger. Every
`status_report.py --strict` run appends one immutable, content-hashed snapshot
here: timestamp, factory git HEAD, all 7 constellation project states, the
claims registry, and any non-verified (CONTESTED / REGRESSED / STALE) evidence
with its commit SHAs.

**Why this directory is versioned (not gitignored like `artifacts/`):**
checkpoints are the durable history that survives context compression —
if they lived under the CI-regenerated `artifacts/` tree they would be
write-only and wiped. Each file is content-addressed
(`<iso-ts>_<sha8>.json`), append-only, and committed as ledger evidence.

**Conventions**
- Never edit or delete a checkpoint file.
- Every new checkpoint lands here automatically when `status_report.py`
  (or `semantic_checkpoint.py`) runs; commit it with the evidence commit.
- To read the latest: `ls -t checkpoints/semantic/ | head -1`
- A checkpoint is the record, not a gate: it never fails a run.

Generated by `scripts/semantic_checkpoint.py`.
